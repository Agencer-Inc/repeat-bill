# bench/results

Published results of the repeat-bill benchmark, one folder per run. **This folder starts empty**:
the first result to land here is the first real run.

```
bench/results/
  README.md                   this page
  index.html                  the results page: generated, never edited by hand
  <date>-<org>-<domain>/      one run
    plain/results.json        the plain arm
    playbook/results.json     the playbook arm
    COMMANDS.md               the exact command lines of both arms
    prices.json               the prices the run used, with a source and a date on every line
```

`index.html` is generated by `bench/publish/render.mjs` from every `results.json` under this folder:

```
node bench/publish/render.mjs --in bench/results --out bench/results/index.html
```

It holds one section per domain and pair of models, and for each run a chart of $ per solved task
by day and a table of its numbers by day and arm. With no results it renders a page that says so.
A file that breaks the schema, or a rule the renderer checks (`bench/METHOD.md` lists them), stops
the render, naming the file and the field, or the run.

How a result gets here: `bench/SUBMIT.md`. What makes a run valid: `bench/METHOD.md`.
