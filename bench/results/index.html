Repeat-bill benchmark

What an agent pays for repeated tool work, asked again with new data: through the Reactor API, against the same large model called directly, and whether the pass rate holds.

A day is a round of tasks, not a calendar day, and the rounds run back to back in one sitting. Day 1 is cold when the reactor arm runs on a Reactor account that has never run this benchmark; its notes say what the harness's key ledger saw of its key. Each later day asks the same kinds of jobs again with new data: in new words, or, where a run says same words, in that job's day-1 words. Saving before Reactor's share-of-savings charge is 1 - reactor / plain on $ per solved task, from day 2 on: Reactor's own charge is not taken out of it. n/a means there is no number to show: nothing passed that day, it was not measured, or, for the plain arm's wrong tool calls, there is nothing to count.

Not all of the small model's spend is visible in a response, so the reactor arm's cost is a floor and its saving is a ceiling.

The method and the rules of a valid run: bench/METHOD.md. How to submit a result: bench/SUBMIT.md.

The playbook arm runs each job through the Reactor API's playbook door, with the harness's bare client playing the customer's own library: it fills what the playbook marks local from the ask and earlier results, and asks the door for every other step. Its saving is read against plain the same way, and its cost is a floor too: it counts what the door's answers name as spent.
